# Scrcpy Harmony 1.0.4-dev.2 开发预发布

状态：**发布准备中，尚未公开**。功能基线为 master `4f6e767`（PR #72 已合入），版本从 dev.1 递增为 dev.2，不覆盖旧附件。采用 Pre-release，稳定版 Latest 保持 v1.0.3。最终 tag/源提交、CI、三平台产物与公开验证将在发布完成后补录。

## 本版范围

- [PR #71](https://github.com/MonsterXia/scrcpy-harmony/pull/71)：HAP 拖入主/投屏窗口安装、覆盖安装成功反馈、跨窗口刷新、大写扩展名和打包探针修正；范围与真机证据见[安装审查](../maintenance/hap-install-review.md)。
- [PR #72](https://github.com/MonsterXia/scrcpy-harmony/pull/72)：桌面退出后 native 投屏会话归属记录和前台受限恢复；接受合法正/反向转发清单，隔离损坏记录，拒绝进程身份不确定的清理，并避免后台预热遮蔽旧记录。详见[投屏恢复记录](../maintenance/screencast-orphan-recovery.md)。
- 继续包含 dev.1 的 Beta Update、语言选择、键盘/粘贴、H.264 与 JPEG 回退；本轮没有新增手机到电脑剪贴板同步。

## 发布计划与验收门槛

1. 同步 package.json、锁文件与 CHANGELOG；发布准备 PR 通过独立复审、test/lint/三个打包启动 CI 后合入。
2. 从同一已确认提交运行 Build，三个平台全部实际安装/启动成功后下载原始 artifact，验证平台、源提交和 ZIP SHA-256。
3. 核对安装包、blockmap、更新 YAML 的版本/文件名/大小/SHA-512，以及各平台签名报告。按 YAML 安全文件名复制上传，字节保持不变。
4. 创建 dev.2 草稿，上传完整附件和 SHA256SUMS/release-validation；重新下载所有附件校验 SHA-256 后公开为 Pre-release，并再次确认 Latest=v1.0.3。
5. 保存发布审计和下载地址，同步 README/RUNBOOK，未验证项继续保留。

## 验证边界

功能基线已在 PR #72 通过 736 项应用测试、Licia 两模式各 606 passing / 4 pending、lint/构建、五项 CI 和独立复审。此前 macOS arm64 原设备的 HAP 双语矩阵、投屏连续重开和强制退出/恢复证据见上述专项；这些不是本版三个安装包的新真机验收。

旧版没有归属记录、删除/切换 profile 或首次写入记录前崩溃时不能自动认领历史会话；数字 PID 的核验与 kill 之间仍存在现有 shell 接口无法消除的极短竞态。跨固件、长时间运行、物理拔插矩阵及 Windows/macOS x64 真机验收仍待补齐。签名、公证及 Gatekeeper 结果以本版附件报告为准，安装启动通过不等于系统信任校验通过。

本版公开后，请下载对应安装包升级；准备期间仍可使用[已发布的 dev.1](https://github.com/MonsterXia/scrcpy-harmony/releases/tag/v1.0.4-dev.1)。设置中的 Beta Update 开启后才会检查开发预发布，更新功能打开具体版本下载页，由用户安装。macOS 13+；语言切换需重启。
