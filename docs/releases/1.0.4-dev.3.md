# Scrcpy Harmony 1.0.4-dev.3 开发预发布

状态：准备中，未发布。功能基线 `0ff05a010ffba11749209e396c38c3677dba88a8`；[PR #75](https://github.com/MonsterXia/scrcpy-harmony/pull/75) 已在最终 head `c5a7e81` 的五项 CI 和独立复审通过后合入，远端并发恢复意见已修正并闭环。用户授权在 PR #75 审查及 CI 通过后合入，规划并发布下一 dev 版本。稳定 Latest 保持 v1.0.3，既有预发布及附件保留。

## 范围

包含 PR #75 的跨电脑投屏残留受限恢复、设备端并发恢复锁、已移除候选兼容，以及应用商店查询截止/取消、缓存/冷却和本地回退。源码修正及真机证据见[独立审查](../maintenance/cross-host-store-review.md)和[合入复验](../maintenance/pr75-merge-review.json)。

本版另外修正 macOS 无证书构建的签名流程：显式 `--adhoc-sign`，在 DMG 安装后执行 `codesign --verify --deep --strict`，签名失败阻止 CI/Build。有配置的开发者证书仍走原签名流程；ad-hoc 不等于 Developer ID、公证或 Gatekeeper 放行。

## 发布计划与验证

1. PR #75 已通过[最终 CI](https://github.com/MonsterXia/scrcpy-harmony/actions/runs/41005676278)并合入。
2. 统一版本和锁文件为 1.0.4-dev.3，独立审查发布准备 PR 并通过五项 CI。
3. 固定同一源 SHA 完成三平台 Build、真实安装启动和 macOS 严格签名验证；发布源必须已合入 master。
4. 核验 artifact ZIP 摘要、安装包/更新 YAML 大小与 SHA-512、签名报告与来源；仅向新的 dev.3 草稿上传固定 14 个附件。
5. 全部附件重新下载校验后公开为 Pre-release，保持 v1.0.3 为 Latest，再验证线上稳定/Beta 通道并归档证据。

## 边界

之前 Mac 真机证据不冒充本版三平台安装包的新真机矩阵；Windows 内网、两台物理电脑切换、其他固件、长期运行仍待验收。原生客户端不参与恢复 advisory lock，最后连接检查与 kill 之间仍有短竞态；离线真实图标未实现。Windows Authenticode、macOS Developer ID/公证状态以实际报告为准，不把安装启动成功解释为系统分发信任通过。

发布准备独立审查修正 PR 环境跳过签名和 ad-hoc 误走公证两项问题：仅无凭据的 PR Mac 打包 step 启用 `CSC_FOR_PULL_REQUEST`，显式 ad-hoc 模式禁用公证。本地 arm64 lint/完整构建、ad-hoc 打包、deep/strict 签名及隔离真实应用启动通过；正式同源 CI/Build 仍待完成。发布工具 11 项离线测试通过，包括两架构各两个签名失败负例；不会以此替代发行附件验收。
