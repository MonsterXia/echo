## 本版修复

- 跨电脑无旧 journal 的投屏残留受限恢复，核验命令、已知库、进程身份和无活动连接；兼容 HarmonyOS socket 表头，设备端锁串行化恢复，已被另一恢复清理的候选不再阻断启动。
- 商店请求三秒截止并取消 HTTP/HTTPS CONNECT 底层连接；并发合并、串行查询、有限缓存和失败冷却避免逐包重复等待，失败返回本地应用字段，网络恢复后无需重启。
- macOS 无证书开发包显式重建 ad-hoc 签名；CI 和 Build 从 DMG 安装后执行 deep/strict 签名校验，失败阻止验收。仅无凭据的 PR Mac 打包步骤启用 `CSC_FOR_PULL_REQUEST`，显式 ad-hoc 模式禁用公证；配置 CSC_LINK 时保留原开发者签名路径。

## 签名与信任

| 平台 | 实际报告 |
| --- | --- |
| Windows x64 | Authenticode `NotSigned`，无发行者签名。 |
| macOS arm64 / x64 | `Signature=adhoc`，无 TeamIdentifier；签名详情和 deep/strict 校验均退出 0，Gatekeeper 退出 3，stapler 退出 65。 |

有效 ad-hoc 签名解决上版包的签名完整性问题，不等于 Developer ID、公证或系统分发信任；未改变全局安全策略。本轮未替换本机已安装应用。

## 公开后的在线更新检查

复用固定发行源的生产 ReleaseProvider、AppUpdater 和真实 HTTP executor，Windows x64、macOS arm64/x64 各检查稳定/Beta 两种设置，共六场景通过：稳定通道选择 1.0.3，Beta 选择 1.0.4-dev.3，三个 Beta YAML 摘要均与发布附件一致；dev.3 不更新自身或降级，dev.2 仅开启 Beta 时提示 dev.3。见[在线报告](1.0.4-dev.3-online-provider.json)。这是 Node 中生产更新逻辑的真实网络验证，不等同三个平台已安装 Electron 的 UI/IPC 更新验收。

## 验证边界与后续

此前 Mac 真机的无 journal 恢复、三轮 H.264、活跃流保护和商店受控断网/网络恢复证据见[独立审查](../maintenance/cross-host-store-review.md)。这些不冒充本版三个安装包的新真机矩阵；Windows 内网、两台物理电脑换线、其他固件和长期运行仍待验收。原生客户端不参与 advisory lock，最后连接检查与信号之间仍有短竞态；未知库或不可确认身份时不接管。离线真实图标和在线图片字节解码未验收。

开启设置中的 Beta Update 才会检查开发预发布；更新入口打开具体版本下载页，由用户安装。旧专项文档的“未发布”“待合入”保留其历史语境，当前交付状态以本记录为准。
