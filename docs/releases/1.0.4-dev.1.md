# Scrcpy Harmony 1.0.4-dev.1 开发预发布

状态：**2026-10-26 21:33（UTC+8）已发布**。基于 master `fe1dfd9`，经 [PR #69](https://github.com/MonsterXia/scrcpy-harmony/pull/69) 合入发布准备；tag/构建源固定为 `1b8f4a98bbf1678f00643055c9ae0553dc482391`。本轮递增开发版本，不覆盖 dev.0；为 Pre-release，稳定版 Latest 保持 v1.0.3。下载地址：[v1.0.4-dev.1](https://github.com/MonsterXia/scrcpy-harmony/releases/tag/v1.0.4-dev.1)。

## 发布验证

- 干净 `npm ci`、lint/词条检查和完整本地 build 通过；Windows 本地应用回归 673 passing、1 项 POSIX shell 用例跳过、0 failed，Licia 生产/fallback 两模式各 606 passing / 4 pending。发布准备及一次性发布脚本均经独立只读复审。
- 同源[五项 CI](https://github.com/MonsterXia/scrcpy-harmony/actions/runs/40330048501)全部通过；[发行 Build](https://github.com/MonsterXia/scrcpy-harmony/actions/runs/40330050058)在 Windows x64 / macOS arm64 / macOS x64 实际打包、安装和启动通过。
- [发布任务](https://github.com/MonsterXia/scrcpy-harmony/actions/runs/40331527706)重新核对三个原始 artifact ZIP SHA-256、安装包及 YAML 版本/文件名/大小/SHA-512、报告源提交，再下载全部 14 个附件核对字节摘要后公开。见[发布审计](1.0.4-dev.1-audit.json)；Release 附有 SHA256SUMS.txt、release-validation.json 及三平台签名报告。本机另下载五个报告/清单文件复核。
- [首次任务](https://github.com/MonsterXia/scrcpy-harmony/actions/runs/40331040270)在上传后读取草稿时中止：GitHub 的 releases/tags 接口不返回草稿。确认原草稿 ID `424286821`、标签与全部附件后，改为按固定 ID 读取，保留原资产并重新完成下载校验；未覆盖 dev.0 或稳定版。一次性操作分支未合入 master。
- Windows 为 NotSigned；macOS ARM64 为 ad-hoc 签名但完整签名校验失败，Intel 未签名；两者 Gatekeeper 未通过，均无 stapled 公证票据。安装启动通过不等于系统信任通过。
- 发布后以本地 dist、隔离用户配置、真实 Electron 菜单/IPC 和在线元数据检查：Beta Update 关闭选中 1.0.3，开启选中 1.0.4-dev.1，当前 dev.1 两者均显示已是最新，不降级。见[脱敏结果](1.0.4-dev.1-online-update.json)。这不是三平台已安装包的完整更新矩阵；临时驱动首次因异步状态等待及关窗后的 IPC 拒绝处理不完整而中止，修正驱动后通过，未修改应用代码。

## 验收边界与下一步

本轮发布验证不替代真机测试。既有投屏恢复设备证据见[控制恢复记录](../maintenance/screencast-control-timeout.md)，语言与更新窗口的源码验收分别见[国际化记录](../maintenance/internationalization.md)和[Beta Update 记录](../maintenance/beta-update-ui.md)。跨固件、长期运行、物理断连矩阵及三平台人工双语视觉仍待验收；跨进程历史视频扩展残留的自动回收未实现。
