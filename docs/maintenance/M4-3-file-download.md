# M4-3 文件下载能力与范围评估

日期：2026-10-23（Asia/Hong_Kong）。状态：**暂缓（评估已记录，路径权限与传输生命周期待验证）**。这是文档评估，不是功能实现或设备验收。

## 结论与来源诉求

[上游 #15](https://github.com/liriliri/echo/issues/15) 请求选择性下载设备文件，举例为 `/data/log/hilog` 中的某些日志文件。2026-10-23 读取时仍开放、无评论；没有给出设备型号、系统/HDC 版本、具体文件或失败输出。不能把它扩展成全盘文件管理器，也不能把现有 HiLog 文本导出当作已满足原始文件下载。

官方 HDC 文档确有 `file recv`，当前项目也通过 hdckit 接收截图。因此“没有文件传输能力”不成立。但官方同时列出敏感日志等可能触发的 `E005008` 拒绝，不能承诺 `/data/log/hilog` 在所有商业设备上可读。现有包装缺少可取消任务、进度接口和完整性/落盘策略，尚不足以直接提供安全可靠的通用下载入口。建议先确定授权路径、目标版本和下述验收范围；满足解除条件后另立实现 PR。

本轮不运行 HDC、不连接设备、不读取设备目录或文件、不安装 HAP、不发布版本。应用样本仅限合成数据或已授权的 bilibili；本轮没有读取任何应用样本。M4-1 音频仍暂缓，与本评估无依赖。

| HiLog 导出 | [Hilog.tsx](../../src/renderer/main/components/hilog/Hilog.tsx)的 `save()` 将当前内存记录拼为文本并调用 `licia/download`。 | 不列举或接收 `/data/log/hilog` 原始文件，也不能保证历史日志、原始压缩格式或字节一致。 |

| 服务端选择 | `ExecCommand` 传递 bin 与 `-t`，没有把 `Client.options.host/port` 转成 `-s`；CLI 可受其自身环境配置影响。 | 后续需验证下载与枚举连接同一服务/设备，尤其自定义端口；本轮未复现服务选择故障，不据此声称当前默认场景必然错误。 |

## 路径权限和版本边界

H1/H2 的接收参数顺序为**远端源路径在前、本地目标路径在后**；文档将二者命名为 DEST/SOURCE，报告使用远端/本地避免混淆。设备调试信任、设备目录权限、桌面目标目录权限是不同边界。

| 路径或能力 | 官方证据与判断 | 后续边界 |
| --- | --- | --- |
| `/data/log/hilog` | H1/H2 有落盘日志导出示例，同时 E005008 说明系统配置、日志等敏感文件可能不允许传输。 | 逐设备/系统/具体文件验证；能列目录不代表能接收文件。拒绝时明确报告，不自动 root、chmod、复制到其他路径绕过限制。不能预先标为普遍支持或普遍不支持。 |
| 普通可读测试文件 | 基础 `file recv` 有官方依据，现有截图调用构成源码复用线索。 | 首轮只考虑用户明确指定、设备允许读取的普通文件；使用合成内容，不扫描整机、不批量导出日志。 |
| 应用沙箱 `-b` | H1/H2 对应 API 15 / HDC 3.1.0e 起，要求调试证书签名且应用已启动；E005004 表示版本不支持，E005102 涉及不存在或越出沙箱的路径。 | 不能把 release 应用、普通 bilibili 安装包或侧载许可视为沙箱可读许可。锁定 recvFile 也无 `-b` 参数；最小范围排除应用沙箱，本轮不查询包或启动应用。 |
| 中文路径 | H1/H2 对应 API 12 / HDC 3.1.0a 起支持。 | 不据此保证空格、引号、换行、超长路径或桌面非法文件名均兼容，需分别验收。 |
| 媒体库 | H1/H2 记载 API 21 起部分路径操作能力。 | 不推定为全媒体权限；照片、视频和其他私有媒体不纳入本任务。 |
| `-sync` / `-z` / `-m` | H1/H2 分别描述按 mtime 选择传输、未开放的压缩参数、同步权限元数据。 | `-sync` 不是字节偏移续传；不将 `-z` 纳入方案，不用 `-m` 解决权限拒绝。首版不承诺续传、权限复制或压缩。 |

## 建议的最小产品范围（尚未实现）

以下为后续范围建议，不能据本报告自动开始实现。先支持用户指定的**单个普通文件**下载；可在同一批准目录的单层列表中逐个选择。批量队列、递归目录、通配符、应用沙箱、链接、FIFO/设备节点、私有媒体、上传/删除/移动均排除在首轮之外。

| 边界 | 后续实现应满足的约束 |
| --- | --- |
| 设备及源选择 | 创建任务时固定 connectKey、源文件和服务端配置，不能在设备切换后把在途任务改投另一台。列表须区分空目录、不可读和断连，提供刷新；只读批准目录，不解析 `ls -l` 的显示文本作为可靠文件名协议。枚举与 stat 的命令/输出格式须独立验证。 |
| 路径处理 | 主进程校验输入、文件类型、允许目录及规范化结果；远端使用设备路径规则，本地使用宿主路径规则。拒绝空值/NUL、路径穿越、危险控制字符与未经支持的参数形态；不能将用户路径拼成 shell 命令。参数数组仍不替代 HDC 自身参数解析和远端链接检查，预检后文件变化也要按失败处理。 |
| 本地保存 | 用户通过保存对话框选择准确文件路径；取消对话框不启动传输。主进程将路径绑定任务，不信任 renderer 随后替换的任意目标；不让远端文件名决定本地父目录。非法文件名、保留名、大小写/Unicode 冲突须提示改名。 |
| 同名文件 | 默认不覆盖；提供取消或另存为。首轮不提供替换既有文件，从创建到最终提交都须保证不覆盖，处理选择之后其他进程新建同名文件的竞争；不能仅依赖先 exists 再写入。 |
| 落盘 | 在所选目录内创建任务独占的暂存目录/文件，传输到暂存位置，验证完成后以经过平台验证的“不覆盖”方式提交到最终路径。保存失败保留旧目标；只清理本任务拥有的暂存产物，不删除源文件。不能只用普通 rename 假定 Windows/macOS 都有同样的原子性和不覆盖语义。 |
| 进度 | 锁定 recvFile 没有进度契约。未取得可靠总量/增量前显示“传输中”，不伪造百分比；若观察暂存文件大小，标明是本地落盘估计，文件增长/轮转时不可作为成功依据。完成必须同时满足命令结果及预期文件类型/长度验证。 |
| 取消/超时 | 任务需拥有可控的本次命令子进程/传输句柄；仅 Promise.race 或隐藏 UI 不等于取消。等待本地写入者停止后才清理暂存文件并进入终态；终止 CLI 是否停止 server/daemon 的写入尚待验证，不能提前保证。禁止以 kill 共享 HDC 服务作为取消；不得中断其他投屏、HiLog、shell 会话。 |
| 失败与恢复 | 分开呈现授权/权限拒绝、源不存在或变化、断连、SDK不支持、磁盘满/只读目录、超时/取消及完整性失败。重试由用户触发，重新确认设备与源状态、创建新暂存文件、从头传输；不自动拼接旧片段。失败或取消不会显示成功，也不自动打开部分文件。 |
| 生命周期 | 明确切换设备、窗口关闭、应用退出的取消/收尾策略；隐藏面板仍挂载，不能把切标签当任务销毁。事件按 taskId/设备过滤，完成与取消竞争只能产生一个终态，迟到事件不得覆盖下一任务。 |
| 数据与诊断 | 文件只保存到用户选定的本地位置，不自动预览执行或上传。报告/公开日志不包含文件正文、设备标识、内部应用目录或原始敏感日志；错误诊断保留类别与脱敏上下文。 |

HiLog 的正在写入/轮转文件尤其需要明确：没有设备快照机制时，长度相同也不能证明内容一致。先用内容固定的合成文件验证源/目标 SHA-256；真实活动日志只能在明确采集时点与一致性限制后单独验收，不宣称取到了事务一致快照。
