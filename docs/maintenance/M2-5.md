### 官方连接、授权和版本前提

- 当前华为文档的无线路径：电脑与设备同网络，设备无线调试页面提供 IP 与端口，执行 `hdc tconn IP:port` 后用 `hdc list targets` 检查网络 key。设备监听端口必须来自当次页面，不能固定写成 8710。当前 HDC 文档仍把 TCP 调试定位为测试环境能力。
- 已读取的官方无线步骤没有独立的 `pair`/配对码命令；USB 步骤明确包含设备端“允许 USB 调试”。这不能证明无线连接无需授权，也不能导入 Android `adb pair` 流程。实际机型是否弹出信任/鉴权提示、是否要求额外前置授权，留给真机记录；不绕过或自动批准提示。
- 当前文档推荐在设备设置中控制调试通道；`tmode usb` 已废弃（OpenHarmony 命令表注明从 HDC 3.1.0e 起）。`tmode port` / `tmode port close` 会重启设备 daemon、打断连接，不是本轮探测步骤，也不把旧“先 USB 后固定端口”的教程作为通用前提。
- 华为当前版本配套表列出：HDC 3.1.0a / API 12（`wait -t`）；3.1.0e / API 15+（包名参数）；3.2.0b / API 20（转发监听地址）；3.2.0e / API 26.0.0+（交互 shell 参数）。这些是对应新增特性，**不是无线调试最低版本表**。未找到足以承诺全部机型无线支持的 HDC/系统组合。
- 真机运行指南对 Wearable 描述为仅无线连接，并排除 Lite Wearable；这只是该指南范围，本应用的投屏、输入和参数读取仍需逐项验收。DevEco Studio 6.1.1.300+ 的 IP Connection 默认屏幕常亮也属于 IDE 行为，不能归因于本应用。

## 命令行目标与现有应用链路

```text
设备无线地址 IP:port ← HDC server 已建立的设备连接
                            ↑
CLI / hdckit → PC 的 HDC server（默认 127.0.0.1:8710）
                            ↓ listTargets / getTarget(key).getParameters()
注册的 getTargets → preload getTargets → Store.refreshTargets/selectTarget
                            ↓
Target 下拉框 option.value = 原始 key → 后续设备方法使用 connectKey
```

1. [主进程](../../src/main/lib/hdc.ts) 以 `Hdc.createClient({ bin })` 初始化。`bin` 来自内置资源或 `hdcPath` 设置，在初始化时读取。没有 `tconn`、`tmode`、配对或网络地址输入处理器；`openHdcCli` 只打开命令行所在目录。应用能消费已有网络目标，不等于应用会建立无线连接。
2. 锁定包的 `dist/Hdc.js` 读取进程环境 `OHOS_HDC_SERVER_PORT`，`dist/hdc/Client.js` 默认 host 为回环地址。CLI 用 `-s` 连接另一台 PC 的 server，与 `tconn` 连接设备是两回事；应用目前没有远程 server host 设置。CLI 与应用必须比较同一 server/端口。不要只比较两个命令名称都叫 `hdc`。
3. `dist/hdc/Connection.js` 直接使用 TCP 与 PC server 握手；收到连接拒绝时会尝试执行配置的 `bin start`。已运行 server 不会因换了 `bin` 自动成为新版本。验收须分别记录客户端、server 和设备版本，不能把自定义路径当作版本配套已成功。
4. `dist/hdc/command/targets.js` / `util.js` 使用 `list targets`，按行取得 key，识别 `[Empty]`；`Target.js` 在参数查询前发送 `shell echo ready`，随后 `GetParametersCommand.js` 发 `shell param get` 并解析 `key = value`。这些过程本轮使用真实锁定包实现。握手 key 缓冲区为 32 字节，因此本轮 IPv4 格式验证也不能证明任意 IPv6/长 key 支持。
5. [getTargets](../../src/main/lib/hdc.ts) 逐目标读取参数、隔离异常，保留 key；[preload](../../src/preload/main.ts) 转发 `getTargets`；[store](../../src/renderer/main/store/index.ts) 按 key 选择、空列表清空选择、缺失旧 key 时选第一个；[设备工具栏](../../src/renderer/main/components/toolbar/Target.tsx) 把原始 key 作为选项值，无 USB 专用格式筛选。
6. 实际 tracker 的增删事件经主进程延迟发送 `changeTarget`。本轮测试仅手工投递该事件和调用刷新；未验证 tracker 断连后的自动恢复、Electron IPC 传输、窗口渲染或投屏恢复。
7. [资源脚本](../../script/resources.mjs) 从 `electron-resources/master` 下载 HDC，未由 npm 锁文件固定可执行文件版本。本轮未下载或执行该二进制；当前发行包、用户自定义 HDC 和设备版本均待现场核验。

### 两项最小失败回归与后续修复建议

- **A：失败被展示成刷新成功。** `getTargets` 的 catch 记录错误后返回 `[]`；store 正常完成；工具栏无条件通知成功。后续在独立任务中定义可区分“正常无设备 / 枚举失败 / 全部参数读取失败”的 IPC 结果或错误传播，并让 UI 有明确的失败提示和再次刷新入口。需协调 `hdc.ts`、公共类型、preload 和设备 UI 所有权；不要仅把所有空列表视为失败。当前回归期望“不显示 success”，不替未来方案指定中文文案。
- **B：文本错误被当作空参数。** `GetParametersCommand` 不区分错误文本与合法但缺失可选字段的参数对象；到 handler 时原文已丢失。后续优先在 hdckit 命令边界识别明确错误并抛出，再利用现有逐设备异常隔离；保持“缺少可选名称/版本字段仍可显示”的 M1-1 约定，不能简单拒绝所有空对象来掩盖输入语义。需要依赖升级/适配与专门测试，本轮不改依赖或生产代码。

这两项是受控输入下的产品行为证据，不作为上游 #13 的已证实根因。无超时/自动重连修复，也未修改由 M2-2 持有的 `hdc/base.ts`。

## 下一轮真机验收步骤（本轮均未执行）

仅在获得单独的设备操作授权及独占测试时段后执行。选择一台明确支持调试的测试设备，不干扰其他对话和共享 HDC 服务。

1. 记录应用构建提交、桌面系统/架构、机型及系统完整版本/API、SDK/IDE 版本。使用明确路径的 HDC 记录 `-v`、`checkserver` 版本和实际 server 端口；只保留脱敏版本结论，不归档设备标识、IP、完整目标列表或原始日志。核对应用启动进程继承的端口和 `hdcPath` 是否一致。
2. USB 基线：由用户在设备端完成调试授权；比较命令行目标和应用列表中的同一测试设备（报告用 `USB-A`）。选择设备、刷新，记录状态和延迟；不打开应用管理/应用列表。本轮没有 HAP，后续如需要侧载只允许用户提供的 bilibili HAP。
3. 无线前提：按该机型当前官方指导，由用户打开无线调试并读取当次 IP/端口。记录是否存在、出现哪些授权/信任步骤、用户拒绝后表现。不得尝试未知配对命令或固定旧端口；若入口不存在，记录机型/构建的具体限制，不能推广为整个系统系列不支持。
4. 在相同 PC server 上，用上述明确路径运行 `tconn <设备页面的IP:端口>`；记录响应类别及耗时。再比较同一 server 的 `list targets` 与应用列表，报告映射为 `NET-A`。需要比较时分别记录“CLI 未列出 / 已列出但参数失败 / 应用已显示”的边界，避免归因为同一种网络故障。
5. USB/无线分别进行连接、用户授权断开、重连。无线端口改变后重新读取页面并连接；检查旧 key 消失、选择状态、新 key 出现、手动刷新与自动更新是否恢复。暂定每种连接重复 3 次，并记录实际观察窗口；自动更新超过 10 秒仍未恢复时保留结果，不宣称通过。投屏/输入回归由投屏任务配合，不以枚举通过代替。
6. 失败场景只针对已授权的测试目标：用户拒绝授权、关闭测试设备的无线调试、目标暂不可达；记录 CLI 错误类别和应用提示。禁止扫描其他地址、修改防火墙、重启共享 server 或删除认证密钥。对已连接的共享目标无任何操作。
7. 恢复原测试状态由用户确认；报告逐项填写“版本、预期、实际、次数/时长、脱敏证据、通过/未通过/未执行”。必须有 USB 和网络真机结果、失败反馈结果和对应 CI，才可重新判断 M2-5 状态。本文连接说明与 fixture 通过均不能满足这一退出条件。
