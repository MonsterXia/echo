# M2-5：设备刷新结果顺序保护

日期：2026-10-22（Asia/Hong_Kong）。基线 `9f8ddcb40c53a822614d8855e7f03901efaba904`，分支 `codex/target-refresh-order`。本轮无真机或 HAP 操作。

## 问题与修复

初始化、tracker 事件和手动刷新都会调用 `Store.refreshTargets()`。旧实现允许任意完成的请求写入列表和选择：新请求已确认空列表后，旧成功请求会重新填回设备；新请求已恢复设备后，旧失败请求会清空设备并显示错误。手动刷新还会为过期结果弹出通知。

每次发起刷新立即递增序号；在 IPC 成功或失败后、发布任何状态之前检查序号。只有最后发起的请求可以发布状态；过期调用返回 `undefined`，工具栏静默结束。有效调用的 `true`/`false` 与原有正常空列表、部分成功和失败恢复语义保持不变。

选择按最新请求的结果更新，不等待较慢的旧请求；如果最新请求尚未完成，旧请求也不得提前写入。这里不串行化、不取消底层命令，不解决永久挂起或请求数量限制；有限命令取消仍由 M2-2 独立推进。
