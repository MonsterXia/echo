## 来源与复现

已读取 [上游 Issue #21](https://github.com/liriliri/echo/issues/21) 和 [PR #30](https://github.com/liriliri/echo/pull/30) 的正文与讨论，两者当日仍开放、无评论。Issue 描述 HDC 命令能列出设备而应用列表为空，但没有给出设备参数或错误堆栈，不能直接认定其现场根因。PR 候选提交 `f8084bbb65eb63a0d759187882de155005936e36` 提议逐设备隔离和防御解析；本次据当前源码重新建立回归，没有直接导入上游测试脚本。

本仓库原 `getTargets` 在整个 `Promise.all` 后统一捕获错误，任一 getTarget/getParameters 或版本解析失败都会返回 `[]`，连正常设备也被隐藏。`softwareVersion.split(/\s/)[1]` 假设字段存在且有第二段；`slice(0, indexOf('('))` 在没有括号时使用 -1，导致 `OpenHarmony 4.1.0` 被截成 `4.1.`。最外层的 listTargets 拒绝未被捕获，也没有区分空列表与读取失败的诊断。

新增测试直接加载真实 `src/main/lib/hdc.ts`，通过其 init 注册的 getTargets 处理器验证返回结果和日志；仅替换 HDC/Electron 及模块初始化副作用。修复前新增 19 项中 **16 失败、3 通过**，见 [失败日志](m1-1-device-enumeration/before-tests.log)。其中正常带括号版本及已有的单设备状态刷新用例作为兼容性基线保留，未声称它们原来失败。

## 修订行为

- 每个设备各自捕获查找和参数读取异常，成功设备保留原顺序；失败日志带设备 key 和原始原因。
- 版本支持纯数字点分版本、产品名前缀、可选括号后缀、多空白与多词前缀。缺失、非字符串或不可识别值返回空字符串并记警告，不隐藏该设备，也不编造版本值。
- 名称去除首尾空白，缺失时用 connectKey 保持可选择；API 字段去除首尾空白，缺失时返回空字符串，保持 `ITarget[]` IPC 字符串字段契约。
- listTargets 失败记录 error 并返回空列表，正常无连接记录 info，全部设备读取失败另记 warn 和数量；下一次刷新重新读取，不缓存失败结果。

没有修改 IPC 名称/类型、renderer 事件、共享子模块、应用列表解析或投屏逻辑。此修复尚未发布，公开 1.0.2 安装包保持原样。

## 复测方法与验证边界

```sh
npm run build
node script/check-targets-live.mjs release/m1-1-reconnect --reconnect
```

仅连接一台已授权设备。脚本打印 READY 后拔出 USB，保持断开，等 DISCONNECTED 确认后接回。脚本检查真实 changeTarget 推送、列表清空、当前选择清空、select 禁用，再检查原设备和选择自动恢复；它不模拟事件、不主动重启 HDC 服务或修改设备设置。每阶段最长等待四分钟，完成后关闭自己启动的应用并删除临时用户配置。

验收脚本曾出现两次误判，均保留原始失败记录，不计为产品通过证据：

- [异步等待探测](m1-1-device-enumeration/probe-async-wait.json)：Playwright waitForFunction 将异步 predicate 返回的 Promise 当作真值，提前结束等待；断开断言随后失败，当时没有实际拔插。改为 Node 侧明确 await IPC 结果后轮询。
- [原生 disabled 探测](m1-1-device-enumeration/probe-native-disabled.json)及[日志](m1-1-device-enumeration/probe-native-disabled-application.log)：实际拔出后已收到 target change 和空列表日志，但脚本检查原生 select.disabled，最终超时。核对 LunaToolbarSelect 源码与无设备实际 DOM 后确认，组件通过外层 luna-toolbar-disabled 类及 pointer-events:none 禁用。脚本改为检查组件禁用状态，并另记 nativeDisabled；失败时额外保存状态快照。应用源码未因此改动。

修正后的脚本已在同一轮真实应用运行中完成 connected / disconnected / reconnected 三阶段验收，报告 passed=true。两次脚本试跑失败仍保留，不覆盖为成功。

未知格式、损坏参数和混合好坏设备由真实处理器的受控 HDC 测试覆盖，未声称手上存在多台异常真机。只有一台可用设备；更多机型、Windows 真机以及长期连接稳定性不由本项覆盖。
