## 修复与证据边界

- `vendor/packages/hdckit/src/hdc/command/install.ts` 原来仅执行 `hdc install <hap>`。现场内置 HDC 的 `help` 明确将 `-r` 定义为 replace existing application；现在统一使用 `install -r <hap>`，覆盖和首次安装共用此路径，不通过卸载重装处理。仍按进程结果与设备成功文本判定结果，不把 exit 0 等同于安装成功。
- `src/renderer/lib/util.ts` 原来仅在开始、失败时通知，成功后只有刷新。现在每个成功 HAP 返回后显示包含该文件路径的成功通知，简体中文与英文同步；失败不显示成功，多选部分成功仍触发刷新。应用面板与投屏拖放共用此逻辑。
- 原代码在本机首次安装和同版本重复安装均成功。**未复现用户描述的偶发覆盖失败，不能断言 `-r` 已解释全部现场失败**；本次修订消除未显式请求覆盖的缺口。不同签名、降级、存储不足与其他固件仍需各自错误现场。
- 原缺失通知可由源码和先失败后通过的回归确认。新测试同时覆盖参数分隔（含空格路径）、HDC exit 0 返回设备错误、进程失败，以及逐包成功/失败通知时序。
