## 首轮失败与验证边界

[首轮运行 39745364171](https://github.com/MonsterXia/scrcpy-harmony/actions/runs/39745364171) 的 Windows、macOS arm64 两版及 macOS x64 的 1.0.1 通过；x64 的 1.0.2 在卸载 DMG 时报告 `Resource busy`，随后的清理又报告镜像不存在，未进入应用验证。保留 [失败日志摘录](m0-3-update-check/first-run-failure.txt)。验收安装脚本改为失败后查询系统挂载清单，镜像已消失则继续，仍挂载则有限重试；没有强制卸载其他镜像。修订后重新运行整个三平台矩阵，六个安装均完成，18 个更新场景通过。

本次验证真实菜单回调、真实网络、真实 IPC 和提示、系统外链调用；没有替换更新器、修改 app.getVersion、模拟更新事件或改动线上 YAML。没有检查系统默认浏览器的页面内容；外链验收证明操作系统接受了准确 URL。错误场景选择网络失败，未另外注入损坏的 YAML。GitHub 重定向时 electron-updater 主动中止原请求产生的 `ERR_ABORTED` 与受控断网的 `ERR_BLOCKED_BY_CLIENT` 分开判断，最终响应和 UI 结果共同作为依据。

应用提示用户到 Releases 手动下载，本次不宣称完成自动下载安装。签名、公证和真机结论仍以 [1.0.2 发布记录](../releases/1.0.2.md) 为准。本项不替代设备或长时间运行验收。后续任务按 RUNBOOK 进入 M1-1。
