# 投屏初始化和兼容库探测耗时

日期：2026-10-24。继续处理首次打开约 11 秒的问题，无 Java/JRE。

## 分段证据

新增 `script/profile-screencast-start.cjs`：运行生产 CaptureUiDriver / NativeVideo，记录控制 shell、候选库、上传、服务启动、首个编码包及清理耗时，不保存屏幕内容或设备标识。该探针不含 Electron 窗口加载和 Chromium 解码；实际应用另测可见 Canvas，两个口径分别记录。

[优化前真机链路](screencast-start-baseline.json)为 **10933 ms**：控制准备 **3335 ms**，其中固定 sleep 2000 ms；第一候选没有存活进程，却继续 15 次 HDC 套接字查询，无效等待和清理约 **4234 ms**。真正的视频流首包约 **647 ms**，不是 11 秒主要来源。六个库本地校验仅数毫秒，没有取消完整性检查。

## 实现

- UiDriver 删除启动后固定 2 秒 sleep。自己的新 daemon 启动后立即建连；仅初始 Driver.create 握手可在 3 秒预算内重新建连，单次等待至多 1 秒。普通用户 RPC 和结果未知的输入不重放。
- getUiDriver 使用 CaptureUiDriver.initializeControl：检查 SDK、建立握手并执行只读尺寸查询，复用仍健康的控制服务。仅初始准备失败时重建一次；第二次失败向上传递，不循环重启，活动投屏超时不进入此恢复分支。旧有 SDK 更新/初始化恢复仍使用 UiDriver.stop 的 UITest 清理方式，没有宣称完成全局进程所有权重构。
- 候选启动初期允许服务异步出现；套接字未就绪时，连续两次确认本会话扩展进程不存在即停止等待。活进程继续等待，不把启动较慢直接视为不兼容。切换候选前仍确认进程、转发和文件已清理；进程本来不存在时不重复查询第二遍清理清单。
- 在应用 userData/data/native-video 保存成功候选的文件名提示。键由设备标识、ABI、UITest 版本、固件版本及完整资源清单 SHA-256 派生；磁盘不写原始设备标识。固件未知时不持久化，身份变化清除内存提示；缓存内容必须属于清单，不提供任意路径。缓存损坏/不可写不阻止投屏；命中后仍验证本地 ELF/哈希、上传后哈希及真实流握手，失败清除提示并试其余候选。手机端依然只有会话临时副本，不依赖预装库。
- 设备架构/固件/UITest 版本查询在控制服务准备完成后并发执行。**撤回**曾试验的与控制初始化并发：临时 `uitest --version` 会被原 pidof 判断误当成已启动 daemon，产生 ECONNRESET。[失败证据](screencast-start-parallel-rejected.json)保留，最终实现保持先后依赖。

## 验证结果

- 新增回归先失败再通过：就绪即连接且容忍早到 TCP、退出候选快速失败、缓存跨实例复用/隔离/损坏/写失败、健康控制复用及恢复最多一次；另覆盖候选失败清除提示、活进程较慢仍可启动。最终应用 **525/525**，Licia 生产/fallback 各 **606 passing / 4 pending**；lint、main 构建、真实 Electron 合成生命周期 **8/8** 通过。
- [最终无兼容缓存链路](screencast-start-optimized-cold.json)：主动重建控制服务，**5591 ms**，H.264。设备已有控制 SDK，但探针使用新的桌面缓存目录；不等同于全新手机首次安装控制 SDK 的耗时。
- [最终独立进程缓存链路](screencast-start-optimized-cached.json)：复用兼容提示和健康控制服务，**2112 ms**，H.264。
- [实际更新后的应用](screencast-start-app.json)：应用重启后打开至可见画面 **2334 ms**，同进程关闭重开 **2042 ms**，均 H.264、2412×1084。相比原实际应用首次 **11007 ms**，日常重启首开减少约 **79%**。记录中也保留控制复用优化前的界面首次 6021 ms / 重启后 3695 ms，不将其冒充最终构建的全冷界面测量。
- 最终应用 UI 缩放 0.5/1.0 后分别 **2768/2816 ms** 出现新尺寸 H.264 帧；恢复 1.0 后 **5002 ms 绘制 195 帧，38.98 FPS**。保持应用和投屏打开，移除临时观测监听及 inspector。

## 边界和下一步

已经移除已确认的固定等待、反复试错和无条件重建。首次适配新固件仍需试库，当前完全重建的设备链路约 5.6 秒，不能称为所有手机秒开；仅一台设备实测，尚未验证新手机首次控制 SDK 安装、物理拔插、不同固件矩阵及长期运行。HDC 准备仍没有统一全链路截止。后续以这些场景继续校准，M2-2/M2-3 其他验收保持进行中；未提交、推送或发布。

复测先关闭所有投屏，然后执行 `node script/profile-screencast-start.cjs <report.json>`；设置 `SCREENCAST_PROBE_CACHE` 为独立临时目录可验证跨进程偏好。显式 `--reset-control` 会重建测试设备控制服务，仅在已关闭其他 UITest 工具时使用；脚本检测现有视频套接字并拒绝运行。保持动态画面以便另测 FPS。探针最终释放自己的视频资源及新建转发。

后续已加入选中设备后台准备：见[预热与真实点击验收](screencast-preparation.md)。后台仍需控制初始化和试库，最终实际应用在准备完成后点击约 0.6 秒出图，不将该时间等同于全部冷启动耗时。
