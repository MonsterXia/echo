日期：2026-10-26。基线：`46f2e55`；分支：`codex/beta-update`。[交付 PR 与实时 CI](https://github.com/MonsterXia/scrcpy-harmony/pulls?q=is%3Apr+head%3Acodex%2Fbeta-update)。本地实现与验证完成，合入以 PR 的最终审查和 CI 为准；未发布或覆盖已安装应用。

## 用户要求与行为

用户要求 Beta Update 默认关闭，只选最新正式版；开启后在正式版和所有预发布版中选择最高 SemVer。此前检查期间只有菜单变化，等待结束才出现系统弹窗。用户提供 GPT 更新进度 GIF、最新版本结果卡及旧弹窗截图，要求复刻前两者的交互和样式。

- 菜单新增持久化 Beta Update。关闭时同时排除 GitHub 预发布标记与带 SemVer 预发布后缀的版本；开启后包括 dev、beta、rc。只选择版本号最高的已发布版本，不降级。
- 点击后立即创建 400×146 检查窗口，显示动画进度与 Cancel；结果在同一窗口转为紧凑圆角卡片。最新版本卡为 260×234，保留本应用图标、名称和版本。
- 取消关闭界面并中断网络请求；初始化阶段的取消同样有效。重复检查聚焦已有窗口，关闭后可重新检查，旧请求不能污染新结果。
- 有更新时提供对应 tag 的下载页；不自动下载安装。更新不适用于当前系统或分批发布资格时单独提示，不误报已经最新版。错误可关闭后重试。

## 实现与边界

自定义 ReleaseProvider 分页读取公开 GitHub Releases，复用平台 YAML（Windows latest、macOS arm64 latest-mac、x64 latest-x64-mac），验证版本与 tag 一致。REST 返回 403/429 时改读完整公开 Releases 页面，用 parse5 解析固定发布头和分页结构，不执行 HTML，也不从发布正文推断版本标记。结构不明、列表不完整、元数据异常均报错，避免静默选错版本。

列表及元数据共用 30 秒网络预算；API 最多 10×100 条，HTML 最多 10 页，超出明确报错。此预算不包括 electron-updater 自身的异步文件初始化；初始化期间用户仍可即时取消界面。新检查等待上次底层 Promise 清理，避免复用取消中的检查。GitHub HTML 结构属于外部依赖，变化时需要维护解析器。

新增 update 页面、窗口控制器及 getUpdateState/updateAction IPC。主进程只接受当前更新窗口的主 frame 操作。窗口沿用父窗口置顶状态，恢复最小化的父窗口，定位在可见屏幕内；主动关闭使用 destroy，避免异步关闭时快速重开复用旧窗口。渲染订阅有卸载清理，初始快照不能覆盖较新的事件。
