## 确认的问题与修改

1. **正在运行的应用仍为旧代码**：`/Applications/Scrcpy Harmony.app` 的 app.asar 没有 `bundleInstalled` 词条，上一轮只更新源码/dist。GIF 中 Hello World 出现在手机桌面，符合安装成功但没有完成通知。此次额外交付本机可运行应用，而不仅是 dist。
2. **拖入区域受限**：原主窗口只有应用面板内容区处理 drop，工具栏、概览等区域没有安装处理。现在两种窗口的根组件各挂一个 `useHapDrop`，在 document 接收未被处理的文件 drop；局部应用面板只处理高亮，避免一次 drop 调用安装两次。非文件拖放不接管；非 HAP、无设备、路径读取失败有本地化反馈。
3. **全屏通知被挡住**：原通知在 body，投屏全屏元素是 Canvas 的父容器。实际拖入虽产生成功通知 DOM，容器却在全屏子树之外。共享通知在首次创建及 `fullscreenchange` 时同步到当前全屏元素/退出后的 body。
4. **长路径通知越界**：实际 370px 投屏窗口中成功通知宽约 478px，几何断言失败。增加最大宽度、内容换行与图标不收缩；不改通知持续时长。文件路径转义后作为文本显示，`<test>`、`&` 等不会被当作 HTML。
5. **大写 HAP 扩展名**：原拖入仅接受 `.hap`，加入大小写识别后实测原生 HDC 对 `sample.HAP` 返回 exit 0 / `[Fail]Not any installation package was found`。对比含空格和 `<test> &` 的小写 `.hap` 安装成功。现在 hdckit 仅为大小写不同的 `.HAP/.Hap` 建立字节不变的临时 `.hap` 副本，成功/失败后都清理，原文件保留；cleanup 失败只记警告，不将已完成安装误报失败。
6. **跨窗口列表不刷新**：安装成功后主进程广播 `bundleInstalled(connectKey)`。应用面板按当前设备过滤，沿用已有在途刷新合并机制；不再依赖按钮闭包触发。退出/换设备清理订阅，广播遇到关窗错误不会使成功安装变成失败。

安装本身仍使用 `install -r`。不是先卸载重装；测试探针为了验证首次安装才移除专用样本。不能认定上述问题解释了用户所有历史偶发失败；本轮记录了明确复现和最终矩阵。

## 打包应用矩阵

由 `script/check-hap-drop-live.cjs` 使用系统文件支持的 Chromium `Input.dispatchDragEvent` 注入拖放，真实触发 `preload.getPathForFile`、生产 IPC、HDC 与 UI 通知；没有替换安装返回值。主进程仅包装真实安装处理器计数，验证一次 drop 对每个 HAP 恰好发起一次安装。真实清单前后比较只记录布尔结果，不归档个人应用名称。

样本为此前用户提供的 `com.example.testhap` 1.0.0 / 1.0.1，SHA-256 见[样本记录](hap-install.md)。大写、空格及特殊字符样本是升级包的原字节副本；无效 HAP 是测试临时文件。每种语言先清理专用测试包，再执行以下 15 项，最后保留 1.0.1：

| 场景 | 核对内容 |
| --- | --- |
| 主窗口应用内容区首次拖入 | 1.0.0 安装、成功通知、自动出现 |
| 主窗口工具栏升级拖入 | 1.0.1 覆盖、版本自动更新 |
| 主窗口大写/空格/HTML 字符与非 HAP 混合 | 只安装有效包，路径按文本显示 |
| 主窗口坏包 + 有效包 | 失败提示一次、继续安装并成功一次 |
| 主窗口仅非 HAP | 提示不支持，不发起安装 |
| 列表刷新期间拖入 | 不丢失安装完成后的刷新 |
| 一次拖入两个有效 HAP | 恰好两次安装、两次成功通知 |
| 主窗口概览空白区 | 不依赖应用面板命中 |
| 主窗口页面全屏工具栏 | 全屏内成功通知可见 |
| 投屏普通窗口 | 370px 窄窗口通知完整、主窗口刷新 |
| 主窗口和投屏同时拖入 | 两次实际安装、各窗口各一次完成通知 |
| 投屏坏包 + 大写长路径包 | 错误后继续，成功通知不越界 |
| 投屏页面全屏 | 通知位于全屏子树且可见 |
| 投屏全屏坏包 | 失败通知可见，不误报成功 |
| 退出全屏后再次拖入 | 通知回到普通窗口，安装成功 |

以下为初版探针历史证据；其中同版本刷新、刷新重叠和全部终态通知几何的证明不足，已由[独立复审的 v2 证据](hap-install-review.md)补齐。

最终[中文 15/15](hap-install/drop-zh.json)、[英文 15/15](hap-install/drop-en.json)均通过，包含全屏场景结束时仍处于全屏的断言结果。逐项结果和 app.asar 哈希由这两份 JSON 记录。通知截图仅在本地 `dist/hap-validation/` 留作视觉核对，不入库，以免公开临时绝对路径；未保存手机屏幕。

早期失败保留其语境：首轮暴露大写扩展名被 HDC 拒绝，修复后又暴露 370px 窗口通知越界。随后打包探针在退出全屏时遇到 `Document not active`，该轮未判通过；探针改为先聚焦窗口、仅在仍有全屏元素时退出，再完整重跑，生产退出全屏逻辑未因此改动。
