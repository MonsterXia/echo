## 来源与复现

[上游 PR #31](https://github.com/liriliri/echo/pull/31) 当日仍开放，候选提交 `9b7451d708257de1405033b9d9be0ef52d913ce5`，无评论或 review。已读取正文和完整 patch。上游方案在批量 shell 后隔离逐项解析，本次另将 shell 调用纳入各应用边界，不导入上游新增测试命令，也不修改共享子模块。

旧实现有三个相关失败入口：

- 整批 shell 拒绝或集中 JSON.parse 中任意一项失败，都会令 getBundleInfos 整体拒绝，renderer 本批无法继续。
- mainEntry 找不到对应模块、模块为空或能力数组缺失时直接解引用，正常应用也随之丢失。
- `base.shell` 的批量协议按固定 `echo_separator` 字符串切分；该文本若出现在合法元数据中，会破坏结果边界。只过滤失败输出后再按数组下标拼接包名，同样会产生错位。

新增 21 项测试同时加载真实 bundle.ts 与 base.ts，调用 init 注册的真实 IPC 处理器；只替换 HDC transport、在线信息和 Electron 注册边界。对固定基线源码运行，**18 失败、3 通过**，见 [原实现日志](m1-2-bundle-enumeration/before-tests.log)。原来通过的正常路径、能力回退和无 mainEntry 情况作为兼容性基线保留。

## 修订行为

每个包单独执行命令、解析并生成结果，成功项保持原请求顺序，不建立过滤后下标映射。兼容标准包名标题后的 JSON、CRLF 和纯 JSON；检查正文中的包名与请求一致。命令错误文本、损坏 JSON、无 applicationInfo 或包名不符时跳过该项，日志包含设备、包名和原因。共享 shell 及其他调用者不变。

缺失主模块或能力时保留可显示字段、记录警告并省略 mainAbility；不编造启动目标。可选字段缺失时保持原 IPC 的字符串/数字/布尔类型。在线名称/图标读取失败保留本地字段，并记录对应包名；下一次枚举重新读取 bm dump，不缓存失败结果。仍使用原有在线元数据策略，侧载名称与图标留给 M1-3。

逐应用 shell 增加了独立调用次数，renderer 保持原有每五个包一批的加载方式；本次没有并发优化或性能改进结论。
