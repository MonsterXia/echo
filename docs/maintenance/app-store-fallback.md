# 内网应用商店元数据失败回退（2026-10-30）

状态：源码修复、自动回归和 macOS arm64 / 真实手机的受控网络验证完成；交付与审查修正见[独立审查记录](cross-host-store-review.md)。尚未发布新安装包，内网 Windows 包未现场复测。

## 问题与修复

用户提供的 `error.txt` 显示应用商店元数据请求为 `timeout: 0`，连接外网超时后打印完整 Axios 异常。原 `getBundleInfos` 逐包等待该请求，内网下会重复阻塞列表；失败没有缓存，刷新时再次逐包等待。该问题与投屏恢复是不同调用链。

`hdc/onlineBundleInfo.ts` 现在负责可选商店元数据：

- 每次请求有 3 秒总截止、Axios 超时与 AbortSignal。独立 HTTPS Agent 的连接选项传递同一信号，覆盖代理 CONNECT 尚未完成的阶段；结束时取消信号并销毁本次 Agent，不影响其他请求或全局 Agent。
- 同一包的并发请求合并；商店请求串行，使首个网络失败对其他并发批次也生效。网络、服务端和无效响应失败后冷却 30 秒，期间立即返回本地回退；后续查询在冷却结束后可重试，无需重启应用。
- 有效名称/图标地址进程内缓存一小时；HTTP 404 和正常空结果只对该包缓存五分钟，不阻止其他包。最多 500 项；失败的迟到响应不能写回缓存。没有新增磁盘缓存或后台定时重试。
- 外部响应只允许合适的字符串字段进入 IPC；本地名称仍优先。在线失败保留设备名称、版本、安装时间等字段，图标为空时继续使用已有默认图标。
- 日志只记录包名与白名单错误码组成的简短原因，不再输出 Axios request/config、代理凭据、请求正文或设备标识。网络冷却期间不重复打印同类警告。

该修复不改变内网访问权限、系统代理或 TLS 验证，也不使被阻断的商店可访问。它修复可选商店不可用时阻塞应用列表和刷新、异常信息过量以及代理连接未释放的问题。商店首次不可达时仍可能等待一次三秒预算；HDC 本身的命令耗时/断连不属于这个预算。离线真实应用图标仍未实现，不关闭 M1-3 待办；内存中的图标 URL 也不等于图片离线缓存。

## 验证

- 新增的五项业务回归在旧代码上全部失败，随后通过。补充不同批次共享冷却、已有缓存保持可用、迟到响应不污染缓存、缺失条目过期再查。
- `test/online-bundle-info.test.cjs` 使用真实 Axios 与本地 HTTP 服务：三秒取消不回复的连接，冷却期不发请求，时间推进后再次成功。另一项执行真实 HTTPS CONNECT，修复前留下一个活动代理连接，修复后连接为零；没有把 Promise 超时当作底层连接已关闭。
- 专项共 46 项通过；最终全量、lint/i18n、主进程构建及源码摘要见[验证清单](store-fallback/verification.json)。无 renderer/preload/IPC 签名变更。
- [阶段真机报告](store-fallback/fixed-live/report.json)：仅选择 WPS 与 bilibili，真实 HDC、生产 IPC 和应用面板保留。隔离进程的本地代理先接受商店请求但不回复，随后仅转发固定真实商店 API，HTTPS 保持端到端 TLS。第一次两包查询 3765 ms，设备信息保留，只有一个商店请求，超时后代理 socket 为零；应用面板两行显示、离线刷新 1000 ms，额外查询没有再次访问商店。
- 等待 31 秒后，同一进程从真实商店取得两款应用的 HTTPS 图标地址，本地名称和版本保持不变。全程共三个商店请求/隧道，一条简短回退警告、零页面错误。没有保存手机画面、应用列表、原始异常或网络正文。在线阶段验证元数据地址，未单独声称图片字节解码或离线真实图标验收。

独立审查另修正探针超时/关闭/清理误报；最终源码的商店真机复验见 [review-live/report.json](store-fallback/review-live/report.json)，最终全量统计及证据版本见[审查记录](cross-host-store-review.md)。

## 保留的失败与范围

- [第一轮](store-fallback/live/report.json)与[第二轮](store-fallback/live-second/report.json)：本地数据按时返回，但验证代理没有统计 Axios 的 CONNECT，不能把它们算作受控网络验收。
- 补充 CONNECT 后，[第三轮](store-fallback/live-connect/report.json)与[第四轮](store-fallback/live-complete/report.json)发现三秒后连接仍在；第四轮明确处理服务端 FIN/半关闭后仍复现。随后真实 CONNECT 单测先红，补 Agent 连接取消后单测和真机均通过。没有隐藏这些失败或误归为网络恢复通过。
- 测试不安装、卸载或改动手机应用；模拟的是无响应代理，不是公司内网实测。Windows、公司代理鉴权与不同网络策略需在新包现场补验。当前公开 dev.2 及本机已安装应用未替换。

复现：先构建，再运行 `node script/check-store-fallback-live.mjs <证据目录>`；需单台已授权手机且安装上述两款应用。探针保留真实元数据/渲染，选择器限制为两包，临时配置和本地代理在结束后清理。下一步跟进与跨电脑投屏修复共用 PR 的 CI/审查，验证 Windows 包后规划发布。
