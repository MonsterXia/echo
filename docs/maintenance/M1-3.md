## 实际发现与复现

- `bm dump -n yylx.danmaku.bili` 的 label 是 `$string:app_name`，iconPath 是 `$media:app_icon`。两者均为资源引用，不能直接当显示文本或文件路径。
- 模块路径 `/data/app/el1/bundle/public/yylx.danmaku.bili/entry.hap` 的只读访问返回 Permission denied；本轮未尝试提权、安装、卸载或改动应用数据。
- `bm dump -n yylx.danmaku.bili -l` 返回“哔哩哔哩”。[OpenHarmony bm 文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/tools/bm-tool.md#查询应用信息命令dump) 说明该参数自 API 20 提供；实现直接检查设备的帮助输出，不用应用 target API 判断设备能力。
- [原实现联网记录](m1-3-labels/before-online.json)已经取得“哔哩哔哩”和商店图标。因此联网场景属于兼容性回归，不能描述为原缺陷复现。
- [原实现离线记录](m1-3-labels/before-offline.json)：对固定基线的真实 bundle/base 处理器使用真实 HDC，并将在线 HTTP(S) 请求代理到本机关闭端口，结果回退为包名且无图标。仅 IPC 注册边界被替换，没有伪造设备返回值。

本样本设备元数据为 `app_gallery / release`，不能据此宣称 debug 签名侧载已验收；其安装渠道不从该字段反推。

## 修订

优先使用有效的本地明文 label；否则每批请求至多探测一次 `bm dump -h`，支持 `-l, --label` 时逐应用读取设备解析的名称。空值、资源引用、错误/帮助文本、多行和控制字符不会显示为应用名。失败记录设备和包名诊断并保留原来的在线/包名回退，其他应用继续加载。能力和名称不跨请求缓存，重连、重装和语言变化后重新读取。

本地名称优先于商店名称；在线图标策略保留。图标、列表和确认框在 HTML 边界转义名称，保留原文搜索和悬浮提示，避免应用名称中的标记被当作页面内容。独立审查发现图标与确认框的遗漏后，已用受控标签在实际 Electron 中复现并修复；另补本地名称等于包名的优先级回归（修复前失败，修复后通过）。IPC 类型、事件、共享子模块和公开 1.0.2 发行版未变。
