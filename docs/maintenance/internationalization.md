# 应用国际化与开发流程

日期：2026-10-26。基线：`84be73f`；分支：`codex/internationalization`。[交付 PR / 最终审查与 CI](https://github.com/MonsterXia/scrcpy-harmony/pulls?q=is%3Apr+head%3Acodex%2Finternationalization)。源码与本机验证完成，合入以 PR 为准；未发布安装包、替换用户应用或修改手机/系统语言。

## 原因与改动

项目并非完全没有国际化：共享层已有中英文词典和启动语言解析，业务组件也大量使用 t()。实际缺口是业务层 en-US 和 zh-CN 都注册了同一中文字典，设置页没有语言入口，部分按钮引用未定义词条，LunaModal 则按 navigator.language 独立选语言。因此会出现英文菜单混合中文页面、空 tooltip，以及确认框与应用语言不同。

- 新增独立英文业务词典，与简体中文各 **127** 项；共享词典各 **67** 项。补齐 install、iconView、listView、appSwitch、on/off 等缺词，翻译 Beta Update 菜单、HAP 文件筛选名称、遥控器确认按钮。
- 设置页提供系统设置、English、简体中文；选择存储于既有 language 设置，提示用户重启后生效。主进程、窗口标题、模块初始化时的表头、更新窗口及 Luna 确认框采用同一启动语言；HTML lang 同步。
- 独立审查复现语言选择后立即退出会因 FileStore 的 300ms 防抖丢失。低频设置改为专用 SettingsStore，同步写临时文件后替换 settings.json；IPC 返回前完成，窗口状态仍用 FileStore。新增真实子进程立即退出/重载回归，并复验 Beta Update 保存。保存失败向用户提示，renderer 在 IPC 成功后才更新选择。
- 正常化 en/zh 及地区、脚本、下划线形式；中文变体当前使用简体中文，不声称提供繁体翻译。不支持的系统语言兜底英文，异常保存值安全回到系统语言。设置页也正常化旧配置，避免下拉框没有选中项。
- 缺词时 t() 兜底英文，未知 key 原样显示便于诊断。双语目录检查不允许依赖 fallback 漏翻译。
- 新增 `npm run check:i18n`，接入 lint 与应用测试；检查双语 key、空值、重复 key、插值参数一致性、显式 t 调用，以及常见 JSX/可见属性硬编码。动态页签改为显式翻译映射。

## 开发流程

项目 SKILL.md 增加文案改动入口和检查约束，并链接 `references/internationalization.md`：先识别可见文案，选择业务/共享词典层，同时维护双语和占位符，再接入 t()；执行词条/相关测试，最后按受影响界面进行双语视觉验证。涵盖第三方默认文案、初始化顺序、技术数据例外和新增语言要求。architecture、development 及中英文 README 已同步。

skill-creator 的 quick_validate 校验通过。验证器需要 PyYAML，本次仅放入临时依赖目录执行，没有修改项目依赖或全局 Python 环境。独立审查另对 skill 推演“新增带应用名的删除确认提示”，结论及最终源码审查记录在 PR。

## 验证

本地完整应用测试 **674/674**；Licia 两模式各 **606 passing / 4 pending**（既有外部夹具待项）；lint（含 check:i18n）及完整构建通过。额外全仓 TypeScript 检查仍有未修改模块的既有诊断，不声称全仓类型检查通过。

隔离真实 Electron 45 验证采用生产菜单、语言初始化、SettingsStore、preload 和构建 renderer。仅以空设备列表替换设备边界，不初始化 HDC；独立临时用户配置，不触碰当前运行应用。英语启动后通过实际设置控件选中文，确认 IPC 返回后文件已落盘（不等待防抖），立即关闭该隔离进程，再以同一配置启动中文。两轮检查：

## 范围与下一步

国际化针对应用拥有的 UI。HDC/CPU/PID/URL/FPS、日志级别、命令、包名、设备应用名称、系统返回类型、设备日志、属性和数字诊断时间戳保留原始语义；不翻译第三方网页、协议字段或原始错误日志。自动检查不是任意数据流分析，变量、模板、options 和第三方默认文案仍需人工审查。
