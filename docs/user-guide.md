# Scrcpy Harmony 用户指南

## 版本与支持范围

本指南于 2026-10-23 对照公开发行版 [**1.0.2（v1.0.2）**](https://github.com/MonsterXia/scrcpy-harmony/releases/tag/v1.0.2) 和 master `8d1cfab` 核对。发行 tag 指向 `1c545a7`，不是当前 master。下文通用操作入口在两者中均存在，行为差异单独列出；本轮未连接真机逐步走读，核验依据见[版本与指南复核记录](maintenance/M3-3-release-guide.md)。

| 项目 | 当前范围 |
| --- | --- |
| 电脑安装包 | Windows x64、macOS Apple Silicon（arm64）、macOS Intel（x64）；macOS 需 13 或更新版本 |
| 设备 | 通过 HDC 调试的鸿蒙设备；本指南的授权步骤引用华为 HarmonyOS 5 及以上手机/平板说明，不代表所有型号、系统版本和投屏能力均已验收 |
| 连接 | 先使用 USB；网络调试的系统、配对与连接兼容性仍见 [M2-5](../RUNBOOK.md)，本指南不承诺网络连接可用 |
| 浏览器 | 必须运行 Electron 桌面程序；单独打开网页没有设备操作能力，原因见[构建指南](build-guide.md#为什么不能直接在浏览器运行) |

**下载 1.0.2 不会获得 master 的全部修复。** 1.0.2 已包含独立名称/更新源及投屏坐标修复。截至本次核验，以下后续行为仅在 master 源码中，尚未随新 Release 发布：

| 功能 | master 相对 1.0.2 的变化与限制 |
| --- | --- |
| 设备刷新 | 隔离单台设备信息读取失败；枚举失败或全部设备读取失败时显示“设备刷新失败”，正常空列表仍显示“未连接设备”；较早发起的刷新不能覆盖较新请求。未取消底层设备命令。 |
| 应用列表 | 隔离逐应用读取失败，优先使用设备提供的应用名称并保留回退，合并并发刷新；不保证离线真实图标，也不代表真实安装/卸载刷新已验收。 |
| 投屏 | 改善重试、关闭及重新打开时的异步处理，并约束窗口初始/恢复尺寸、适配窄工具栏；原机型异常、物理 DPI 和长时间运行仍待验收。 |
| HiLog | 丢弃暂停/关闭前仍在查询名称的旧记录；恢复不重新发送旧记录，查询失败使用 PID 名称回退。导出范围见下文。 |
| 网页调试与概览 | WebView 精确匹配进程、隔离并发查询并限制本地 HTTP 等待；概览的内存读取增加截止。两者均不是整个查询链的总超时，不代表无线调试或长期卡死已解决。 |

完整验收状态见 [RUNBOOK](../RUNBOOK.md)。本次 master 的包版本仍显示 1.0.2；反馈源码构建问题时需附提交号，不能仅凭“关于”中的版本判断是否包含以上修复。下载其他版本时，以该版本 Release 和对应 tag 为准。

## 下载与安装

1. 打开本仓库 [Releases](https://github.com/MonsterXia/scrcpy-harmony/releases)，展开目标版本的 Assets。下表对应本次核验的 [v1.0.2](https://github.com/MonsterXia/scrcpy-harmony/releases/tag/v1.0.2)。普通用户下载安装包，不下载 Source code、`.yml` 或 `.blockmap`。
2. 1.0.2 的文件对应如下。Mac 可在苹果菜单“关于本机”查看芯片或处理器。

   | 电脑 | 安装包 |
   | --- | --- |
   | Windows x64 | `Scrcpy-Harmony-1.0.2-win-x64.exe` |
   | Mac Apple Silicon | `Scrcpy-Harmony-1.0.2-mac-arm64.dmg` |
   | Mac Intel | `Scrcpy-Harmony-1.0.2-mac-x64.dmg` |

3. Windows 双击 exe，按安装向导选择目录并完成安装；Mac 打开 DMG，将 Scrcpy Harmony 拖到“应用程序”，从“应用程序”启动。
4. 在应用的“Scrcpy Harmony → 关于 Scrcpy Harmony”查看版本。更新入口为同一菜单下的“检查更新”；发现更新后会引导打开 Releases，需手动下载安装。

**1.0.2 未做发行者签名或 macOS 公证，Gatekeeper 检查未通过。** 校验值及安装启动证据见[发行记录](releases/1.0.2.md)。若系统阻止运行，先核对下载来源及校验值；Mac 在确认来源可信后，可按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)于尝试打开后进入“系统设置 → 隐私与安全性 → 仍要打开”。受管理电脑可能不允许例外；这不表示安装包已获签名或公证。

安装包已包含 HDC 与投屏所需资源，日常使用不需要安装 Node.js、npm 或自行编译。

## 开启调试并连接设备

以下设备设置步骤适用于华为文档所述的 HarmonyOS 5 及以上手机/平板。其他设备请查看对应系统的官方说明；菜单文字和重启提示以设备实际界面为准。

1. 在设备“设置”中搜索“软件版本”，连续点击软件版本 7 次，按提示启用开发者模式；若提示重启，完成重启后再继续。
2. 进入“设置 → 系统 → 开发者选项”，打开“USB 调试”。这两个步骤依据[华为官方说明](https://consumer.huawei.com/cn/support/content/zh-cn16030363/)，这里只引用开发者模式和 USB 调试步骤，无需为了 Scrcpy Harmony 执行该文章的手机助手备份流程。
3. 用支持数据传输的 USB 线连接电脑，解锁设备。设备出现“允许 USB 调试”提示时，仅对自己信任的电脑允许；授权提示可参照[华为真机连接说明](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/ide-hmos-run-device)。
4. 启动 Scrcpy Harmony，在主窗口设备下拉框旁点“刷新”。成功后下拉框显示设备名称，选择要操作的设备。多台设备连接时，每次操作前确认选择。

下拉框会显示设备标识；不要将未遮盖的设备选择框或概览截图贴到公开 Issue。若显示“未连接设备”或 master 中的“设备刷新失败”，按下方排错表检查。刷新成功提示本身不代表已有可用设备；正常空列表仍可提示刷新成功。

## 投屏与输入

1. 选中设备后，点击设备下拉框旁的“投屏”图标，等待独立投屏窗口出现画面。
2. 在画面上点击，或按住鼠标拖动后松开，发送触摸操作。工具栏提供“返回”“主界面”、音量及“电源”按键。
3. 要输入文字，先在设备画面中点中目标输入框，再点击工具栏“输入文本”，在弹框中输入或粘贴文本并确认。它是一次文本发送操作；没有承诺电脑与设备剪贴板自动同步，也不能把电脑的粘贴快捷键当作设备粘贴。不同输入框、中文和多行文本的兼容性需以实际结果为准。
4. “投屏分辨率比例”可选 0.5–1.0，调整会重新请求画面；另有“置顶”“全屏”“截屏”。截屏导出当前投屏画面为 `screenshot.png`。
5. 关闭投屏窗口可返回主窗口。切换设备前先关闭投屏，选择新设备后再打开，便于确认操作对象。

当前未提供音频转发、自动剪贴板同步或独立的“保持投屏但让手机息屏”功能；“电源”发送的是设备电源键，不能据此保证息屏后持续投屏。受保护内容、特定应用卡死、横屏/旋转和特定机型的验收边界见 [RUNBOOK 阶段 2、4](../RUNBOOK.md)。

## 日志导出与问题反馈

### 设备 HiLog

1. 选择设备，切到主窗口的“日志”标签，等日志出现。可用级别、包名和标签筛选显示内容。
2. 在复现前点“清除”，只采集必要的短时间段；复现后点“暂停”。切离日志标签也会暂停未手动暂停的流，切回来继续。
3. 点工具栏“保存”，将文本下载保存到电脑；默认文件名由设备名称和时间组成，扩展名为 `.txt`。需要局部内容时，可选中文字后用右键“复制”。
4. **保存会包含本次已接收的全部记录，包名/标签/级别筛选仅影响显示，不会裁剪导出文件。** 分享前用文本编辑器保留相关片段，删除设备标识、账户、内部应用名称、私有地址和其他无关信息，并将含设备名称的文件名改为中性名称。不要公开完整应用列表。

“清除”和“重启”会清掉本窗口已收集的记录。公开发行版 1.0.2 中，暂停或关闭前仍在查询 PID 名称的记录可能稍后到达；本次核对的 master 已丢弃这些旧记录，暂停后再继续也不会重新发送它们，查询失败则保留日志并使用 `pid-<数字>` 作为名称（见[无设备验证与版本边界](maintenance/M3-3-hilog.md)）。这不是已发行能力，也不代表取消了底层查询。“清除”仍只是清空窗口记录，且已发送的 IPC 可能仍在传递，因此这些按钮不是严格的采集时间边界。导出后按时间戳核对并裁剪所需范围，再做脱敏。此处导出的是设备 HiLog，不是 Scrcpy Harmony 主进程日志，也不是历史日志备份。

### 桌面程序错误

当前没有“一键导出全部诊断日志”菜单，也没有承诺自动写入某个固定日志文件。可从“帮助 → 切换开发人员工具”打开当前窗口的开发人员工具，在 Console 中复制相关错误；主进程控制台日志与页面 Console 不等价。源码开发启动时可保留启动 Electron 的终端输出，步骤见[构建指南](build-guide.md#开发启动)。发行版没有开发模式专有的“打开用户数据目录”“调试主进程”菜单。

从“帮助 → 报告问题”进入[本仓库 Issues](https://github.com/MonsterXia/scrcpy-harmony/issues)。报告应用版本（源码构建附提交号）、电脑系统/架构、设备型号及 HarmonyOS/HDC 版本（若已知）、复现步骤、等待时长、预期与实际结果，以及经过脱敏的错误片段。不知道 HDC 版本时可以注明使用内置 HDC，不必上传完整设备信息。

## 常见失败

| 现象 | 检查与下一步 |
| --- | --- |
| “未连接设备”或投屏按钮不可用 | 确认 USB 线能传数据、设备解锁、USB 调试已开启并授权；重新插拔后点击刷新。Windows 若设备管理器显示驱动异常，按设备厂商的当前官方驱动说明处理。记录错误后反馈；1.0.2 尚未包含 master 的枚举异常隔离修复。 |
| “设备刷新失败”（master 源码构建） | 表示本次枚举或全部设备信息读取失败，与正常空列表不同；旧设备选择会清空。检查连接、授权和 HDC 设置，恢复后再刷新并记录脱敏错误。部分设备读取成功时仍可显示可用设备，不代表所有连接设备都读取成功。 |
| HDC 路径错误或不同工具连接结果不一致 | 打开主窗口齿轮“设置”，检查“HDC 位置”。默认留空使用内置 HDC；指定外部 HDC 时选实际可执行文件，按提示重启应用。多个开发工具可能共用 HDC 服务，勿在他人调试期间终止服务。 |
| 退出应用导致其他调试工具断连 | 检查设置中的“退出时关闭 HDC”；默认关闭。共用 HDC 时保持关闭。 |
| 投屏空白、卡住或触摸不准 | 先确认选中设备仍连接且亮屏，关闭投屏再重新打开；记录是否仅某个应用发生、比例、设备方向与桌面缩放。不要把已有坐标修复当作全部机型已通过。 |
| 文字未输入 | 先点中设备输入框，再使用“输入文本”；先用短文本定位问题，记录输入法、字段类型及字符范围，勿用密码作为测试文本。 |
| 应用列表空白、名称是包名、图标缺失 | 1.0.2 和 master 行为有差别；master 的失败隔离/名称回退仍不保证离线真实图标。先刷新并记录版本及网络状态；无需安装、卸载或清除应用数据来采集反馈。 |
| “网页”标签没有目标 | 设备应用须有可发现的调试目标；列表为空不能直接证明 USB 断连。目标发现兼容性仍在 M2-4 待验收，不承诺所有 WebView 可调试。 |
| 更新检查失败 | 检查是否能访问本仓库 Releases，稍后重试或手动下载；应用不会自动回退到上游 ECHO 更新源。 |

## 从 ECHO 切换

Scrcpy Harmony 使用独立应用 ID `io.github.monsterxia.scrcpyharmony` 和新的用户配置目录。旧 ECHO 配置保留原处，**不会自动迁移**。首次启动按新应用重新设置主题、HDC 位置和窗口偏好；没有配置导入向导，不建议把旧配置目录整体覆盖到新目录。它们可分开安装，但 HDC 服务仍可能共享，应用名称隔离不等于调试服务隔离。
